# How do you control what an AI agent is allowed to do?

You control an agent by giving it an owner and explicit limits, checking those limits at the moment of the action rather than at sign-in, and keeping a record of what was decided. The check must be able to refuse, and a refusal must stop the call.

## The short answer

An agent needs three things before it can be trusted with a real action: an identity that names the agent and the person or team behind it, a permission that says what it may access, spend or change, and a check that runs before the action and can stop it. A prompt instruction is advice the model can be talked out of. A limit enforced in the caller that owns the tool holds.

## Set the limits

| Limit | What it does |
| --- | --- |
| Allowed actions | Only the listed actions can run |
| Denied actions | Always blocked, and a denial wins over an allowance |
| Human approval | Irreversible actions wait for a person |
| Spend cap | Caps how much the agent can pay |
| Expiry | Permission ends on the date you set |
| Revoke | Permission ends the moment you revoke it |

A missing, expired or revoked permission grants nothing. [Control agent actions](/use-cases/control-agent-actions) covers each field with examples.

## Check at the boundary

The check runs where the tool call happens, before the call. A log entry written afterwards only describes what already ran.

```text
Agent          report-agent
Action         Publish report
Authority      Draft   ✓
               Publish ✕
Decision       Blocked
```

```ts
import { evaluateRuntimeAction } from '@proofable/sdk/runtime-mount';

const decision = evaluateRuntimeAction(mount, 'publish_report', { irreversible: true });
if (!decision.allowed) throw new Error(`${decision.code}: ${decision.message}`);
```

[First guarded action](/mcp/guarded-action) walks through the same call with every decision code.

## Keep proof of each decision

Each check can leave a proof that records which agent acted, which permission applied, and whether the call was allowed or refused, so the next system can check it without repeating the work. [Prove what happened](/use-cases/prove-what-happened) and [Reuse verification](/use-cases/reuse-verification) cover the record and its reuse.

## Common ways this goes wrong

- **The agent has no owner.** Without an owner there is nobody to hold responsible and nobody who can revoke.
- **Permission never expires.** An approval given once stays live until someone remembers to remove it. Set an expiry.
