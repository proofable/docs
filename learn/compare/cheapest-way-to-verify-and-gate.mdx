Cheapest depends on how many times the same fact gets checked. A per-check vendor bills again on each visit. A proof is created once, then read without a fee, so the more places that need the same answer, the wider the gap between the two.

## Which to choose

- **Choose a reusable proof when the same fact is asked again,** by your next session, another service, another agent, or a buyer. The first check is paid. Every later check costs 0 credits.
- **Build it yourself when one team owns both the rule and every caller,** and a row in your own database settles every question you ever ask.
- **Pay a per-check KYC vendor when a regulator requires you to retain the document itself.** Record its pass as a proof, and no downstream service pays for that answer again.

## What a proof can cover

Each check proves one fact to a stranger without handing over the data behind it.

- **A real, unique person.** [Proof of human](/verification/proof-of-human) reads the passport or ID chip on the person's own phone through ZKPassport. It can confirm an age threshold, a nationality outside a list of countries you set, the issuing country, and a face match against the document photo. Proofable keeps the yes or no answers, never the document.
- **Ownership.** Control of a wallet, a domain, a social or organization account, an NFT, a token balance, or a contract.
- **Risk.** A [wallet risk](/verification/wallet-risk) check before funds or access move.
- **Agents.** Agent identity, delegation, spend caps, and permission records, checked on every plan.

## Add it in one command

```bash
npx -y @proofable/sdk setup
```

That registers the hosted MCP server and installs the workflow skill, so an agent can check permission before it acts. Servers and CI use an [access key](/deployment/access-keys) instead of browser sign-in.

```ts
import { ProofableClient, defineGate } from '@proofable/sdk';

const client = new ProofableClient({ apiKey: process.env.PROOFABLE_ACCESS_KEY });
const gate = defineGate([{ verifierId: 'proof-of-human' }]);
```

The gate runs on your server, so your server keeps the final decision. [Gates](/gates) covers the widget, the checkout, and pay-per-call, and [build a platform](/use-cases/build-a-platform) wires it into your own product.
