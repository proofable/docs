This page records Proofable's behavior for the AAIF working-group use case
*"authorization when the escalation authority is unreachable."* It follows the same three headings
the group uses — **enforced behavior**, **known gaps**, and **separate simulation evidence** — so a
reviewer can compare implementations without mixing evidence.

The behavior below is the deployed protocol, read live. Every claim names what was run, on which
revision, and where it stops.

## Enforced behavior

An agent's authority is the delegation proof it presents, not a scope string. Every dispatch pins an
explicit `delegationQHash`, and the authority is re-validated at the moment of dispatch. A missing,
expired, or revoked permission fails closed.

| Case | Deployed behavior |
|---|---|
| **Binding veto** | A grant that omits `run_command` is refused **before an executor is assigned**. |
| **Stale evidence** | A revoked grant replayed is denied with `DELEGATION_PROOF_DENIED`; **no job is created**. |
| **Revocation after dispatch** | The in-flight job's terminal state is read after the grant is revoked; the boundary between refused authority and an already-committed effect is recorded explicitly. |
| **Human approval** | An approval-gated job parks, an authenticated decision is accepted, and it completes. Without approval it is cancelled; a late approval cannot resume it. |

Every intercepted dispatch persists a signed **authority-decision receipt** — outcome, reason code,
controller and agent identity, the pinned delegation, and an args digest — so a denial is auditable,
not silent. Receipts are private by default.

## Known gaps

Stated plainly, because the group's value is in the comparison, not in a perfect row.

<AccordionGroup>
  <Accordion title="Remote authority unreachable does not apply to this path">
    Proofable checks current authority state locally at dispatch, so this path has no remote
    authorization service that could become unreachable. The packet records the case as **not
    applicable to the current path**. The engine has a fail-closed gateway branch for a remote
    authority, and that branch has **not been run live**.
  </Accordion>
  <Accordion title="Self-operated, no independent peer witness">
    The run is self-custodied: an ordinary non-admin Pro review tenant drives it with a dedicated
    agent. There is no independent peer witness and no second tenant on the public surface. The
    reproduce kit below lets another operator run the same cases; no independent run is published yet.
  </Accordion>
  <Accordion title="Committed effect and recovery are the relying party's fields">
    After a decision, committed effect, retries and recovery belong to the relying party. Proofable
    fills what its records carry and marks the rest *outside the implementation*.
  </Accordion>
  <Accordion title="A public mount is narrower than the protocol engine">
    The published `@proofable/sdk` mount evaluator does not expose a per-call delegation chain, a
    per-user rate counter, a second tenant, or an unreachable-gateway path. Those are declared, not
    scored.
  </Accordion>
</AccordionGroup>

## Evidence

The current packet is run `aaif-e1217327a-20261008` on live production, protocol revision
`e1217327a`. It holds all eight suite cases, with 15 signed envelopes that anyone can verify offline
and checksums over the published bytes. No account is needed to read or check it.

| Scenario | Result |
|---|---|
| Binding veto | **Supported.** The protected action is refused before an executor is assigned. |
| Revoked or stale authority | **Supported.** Revoked grants are denied; the never-revoked control is accepted. |
| Human approver unavailable | **Supported.** The job is held with no executor, the hold ends without execution, and a late approval is refused. |
| Remote authority unreachable | **Not applicable to the current path.** See Known gaps. |
| Revocation after dispatch | **Supported.** The earlier effect and the refused next dispatch are recorded separately. |

To check the packet yourself, run these in the packet folder:

```sh
sha256sum -c SHA256SUMS
npm install @proofable/sdk@0.1.6
node verify-portable-proofs.mjs
```

Custody is `SELF`: Proofable ran it under a non-admin review profile. The disclosed envelopes are
signed by the Proofable service wallet, and the controller is the subject of each statement.
Revocation latency was not measured. This packet is bounded implementation evidence, not a matched
or certified result.

## Run it yourself

The [reproduce kit](https://github.com/proofable/docs/tree/main/public/evidence/aaif/authority-at-dispatch/reproduce)
runs the same eight cases against the live hosted service under your own Pro account, agent wallet
and grants, then checks every record offline. You keep custody of everything it writes, and
Proofable never sees your agent key. From the kit folder:

```sh
npm install
export PROOFABLE_ACCESS_KEY=npk_...
export AAD_OPERATOR="Your Organization"
node aad.mjs setup
node aad.mjs run
node aad.mjs verify runs/<run-id>
```

Cases: `hosted_allow`, `binding_veto`, `approval_reachable`, `approval_unavailable`,
`revoke_before_dispatch`, `expiry_before_dispatch`, `stale_authority`, `post_dispatch_revoke`.
