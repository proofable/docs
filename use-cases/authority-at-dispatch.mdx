When an agent asks to run a job, Proofable checks the agent's permission at that moment, before any
executor is assigned. A missing, expired, or revoked permission is refused. Every decision leaves a
signed record that anyone can open and check without an account.

## Eight cases on the live service

Recorded on October 8, 2026 on production, under an ordinary Pro account with a dedicated agent.
Each link opens the public record.

## Check it yourself

Open any record above. To verify all 15 signatures offline, with no account and no call to Proofable:

```sh
git clone https://github.com/proofable/docs
cd docs/public/evidence/aaif/authority-at-dispatch/2026-10-08-eight-case
sha256sum -c SHA256SUMS
npm install @proofable/sdk@0.1.6
node verify-portable-proofs.mjs
```

Each record prints `PASS`. They are signed by the Proofable service wallet
`0xA41494e1E5F9E5Eaf786961e6ef84cd1a3071Eec`; the account that ran the job is the subject of each record.

## Run it yourself

The [reproduce kit](https://github.com/proofable/docs/tree/main/public/evidence/aaif/authority-at-dispatch/reproduce)
runs the same eight cases on the live service under your own account, agent wallet, and permissions,
then checks every record offline. The records it writes are yours, and Proofable never sees your
agent key. Running jobs needs Pro. Reviewers get Pro at no cost: email
[dev@proofable.me](mailto:dev@proofable.me) with your account handle.

```sh
npm install
export PROOFABLE_ACCESS_KEY=npk_...
export AAD_OPERATOR="Your Organization"
node aad.mjs setup
node aad.mjs run
node aad.mjs verify runs/<run-id>
```

## Limits

- Proofable ran these cases itself. No independent operator run is published yet.
- The approval window on the live service is 24 hours. This run ended the hold by cancelling it rather than waiting the window out.
- The time a revocation takes to reach the check was not measured.
- Effects at the target system are recorded as Proofable observed them, not by an independent witness.
- Permission is checked locally on this path, so the case of a remote permission service going down does not apply.

These records are Proofable's row in the
[AAIF Identity & Trust working-group comparison](https://github.com/aaif/wg-identity-and-trust/issues/13).
The group's shared reader passes the earlier six-case packet from the same run.
