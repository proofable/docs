Decide what must already be true, then enforce it where the action happens. Publish a listing for a saved `gateId`, price, or schedule. Field reference: [Gates](/gates).

## Choose what to protect

| Protect | Use |
|---|---|
| A page, feature, or download | `VerifyGate` in your app and `gateCheck` on your server |
| Paid access or a digital product | A paid listing with hosted checkout |
| An API | [Pay per call](/gates/pay-per-call) with a proof check |
| An agent action | The agent's permission check. [Control agent actions](/use-cases/control-agent-actions) |

## Define a gate

<Steps>
  <Step title="Write the policy in your app">
    ```js
    import { defineGate } from '@proofable/sdk';

    const gate = defineGate([{ verifierId: 'proof-of-human' }]);
    ```

    You do not need a dashboard visit or a published listing to start.
  </Step>
  <Step title="Add it to your app">
    ```jsx
    import { VerifyGate } from '@proofable/sdk/widgets';

    <VerifyGate gate={gate} onVerified={grantAccess}>
      <ProtectedContent />
    </VerifyGate>;
    ```

    Not using React? Send people to Hosted Verify with `getHostedCheckoutUrl`, then confirm on your server.
  </Step>
  <Step title="Confirm on your server">
    ```js
    const result = await client.gateCheck({
      gate,
      subject: { accountId: user.accountAddress },
    });

    if (result.satisfied !== true) {
      // Send the visitor back to verify
    }
    ```
  </Step>
</Steps>

## Who pays

Sponsored usage, visitor checkout, or pay per call. Details: [Pricing](/pricing)

## What people receive

After they pass, and pay when the gate has a price, Proofable delivers what you attached: access, a redirect, a download, or a revealed value. The value stays hidden until then. Their proofs stay with them for the next gate.
