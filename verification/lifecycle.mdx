## Stages

| Stage | Meaning |
|-------|---------|
| Start | Hosted, SDK, or API |
| Accepted | Request in flight |
| Processing | Async check |
| Complete | Proof ID ready |
| Reused | Checks, gates, and MCP |
| Stale or revoked | Policy or owner revoke |

## Strategies

`VerifyGate` takes a `strategy`:

| Strategy | Use |
|----------|-----|
| `reuse-or-create` | Default. Reuse a valid proof, or create one |
| `reuse` | Read-only checks |
| `fresh` | Force a new result |

## Freshness

Point-in-time checks such as balance and risk go stale. Pass `since` or `sinceDays` to `gateCheck` to require a recent proof, and run a new check only when your policy needs one.

## Revoke

The proof owner signs the revocation.

```http
POST /api/v1/proofs/revoke-self/{qHash}
```

```javascript
await client.revokeOwnProof(qHash, wallet);
```

[Proofs](/proofs) covers the proof record and `qHash`.
