Proofable lets a person or an AI agent take a real action under a limited, current permission,
and leaves a signed record anybody can check afterwards without asking us.

This page is everything we have measured so far. Every number says what it was measured on.
Nothing here is a model benchmark and nothing here is a ranking. Last rebuilt 2026-10-17.

## The three things we measured

### 1. Real actions, on the live service

We ran eight situations that cover the ways permission can go wrong: the grant was revoked; the
grant expired; the action was outside what the grant allows; the person who has to approve could
not be reached; the approval arrived too late. Each one either completed and left a signed record,
or was refused with a reason and no executor was ever assigned.

| What we counted | Number |
| --- | --- |
| Situations that ended the way the contract says | 8 of 8 |
| Signed records that check offline, without our code | 15 |
| Same situations rerun from scratch by a fresh operator agent | 8 of 8 |
| Slowest single situation in the rerun | 121 s |

This run belongs to Proofable. An operator with a Pro account can rerun the same eight situations
against the live service under their own account and keys; the records then belong to them.

### 2. The permission check is cheap, and it refused nothing it should not have

The same five coding tasks, the same model, the same environment and the same grader, run twice:
once with our permission check in the loop and once without it. Only the check differed.

| What we counted | With the check | Without it |
| --- | --- | --- |
| Times the check made a decision | 98 | not applicable |
| Actions the check refused | 0 | not applicable |
| Total time the check added | 467 ms | 0 |
| Average time per decision | 4.8 ms | not applicable |

It never said no on these five tasks, so nothing was blocked. The number of tasks solved did differ — 1 with the check and 2 without it — and that is stated rather than left out. Five tasks at one attempt each cannot support a conclusion in either direction. What this run does support is the cost of a decision and the fact that no action was refused.

### 3. Checking a result a second time is nearly free

The first time a result is produced, it costs whatever the work costs. Every time after that, a
later party only has to check the signed record.

| What a later party pays | Cost |
| --- | --- |
| Produce the result once (grant, action, record) | 37 s |
| Read the record online, no account needed | 0.15 s |
| Check the signature offline, no account needed | 4 ms |
| Model tokens spent on a later check | 0 |

## What we have not measured

Stated rather than left blank, because an empty space in a measurement is the easiest place to
mislead.

- revocation latency
- target-side effect by an independent witness

## Check it yourself

The records are versioned in a public repository and need no account to read or verify. The
eight-case run and its checksums are under public/evidence/aaif/authority-at-dispatch in that
repository.

```sh
cd ../docs/public/evidence/aaif/authority-at-dispatch/reproduce && npm install && node aad.mjs setup && node aad.mjs run && node aad.mjs verify runs/<id>   # authority at dispatch, any Pro account
```

Nothing on this page is generated by hand. It is rendered from the same record as the JSON a
machine reads, and a check fails if the two ever disagree.
