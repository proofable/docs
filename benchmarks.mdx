## Refused before it runs

We tried each way an agent's permission can fail: revoked, expired, outside its scope, waiting on a
person who never answers, and revoked while a job runs. Valid permission ran normally. Each case is
a public signed record: [see all eight](/use-cases/authority-at-dispatch).

## Permission check inside a coding agent

Measured October 1, 2026 on five Terminal-Bench 2.0 tasks, one attempt each. This run used a local
copy of Proofable's permission-check code inside the agent's own process, with one fixed permission
that allows running commands. It made no call to the live service and produced no signed record.

The check made 98 decisions and added 467 ms in total, about 5 ms per decision on average. The timer
used here ticks about every 15.6 ms, so the figure is an average over all 98 decisions and cannot
time a single call. The check refused nothing, so no task was stopped by it. With the check on, the
agent solved 1 of 5 tasks; with it off, 2 of 5. Five tasks at one attempt each are too few to tell
whether the check changes how many tasks get solved.

## Verifying later is free

On October 17, 2026, producing one result on the live service took 2.79 s of job time and 2,426 AI
tokens. The full kit case around it, including granting the permission, took 37 s. Anyone can then
verify the result's record offline in 4 ms, the median of 10 checks on one record, with no account
and no AI model.

## Verify it yourself

```sh
git clone https://github.com/proofable/docs
cd docs/public/evidence/aaif/authority-at-dispatch/2026-10-08-eight-case
sha256sum -c SHA256SUMS
npm install @proofable/sdk@0.1.6
node verify-portable-proofs.mjs
```

To rerun the live cases on your own account, use the [reproduce kit](/use-cases/authority-at-dispatch#run-it-yourself).
The cases run agent jobs, which need a Pro account today.
