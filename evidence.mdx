## What Proofable adds to the AI stack

| Layer | How teams do it today | What breaks in production | What Proofable does instead |
|---|---|---|---|
| **Agent governance & tool gates** | Local tool prompts in Claude Code, Cursor or Codex, or a stateless API/MCP proxy gateway | Local prompts have no owner, cross-agent rules or spend cap. A stateless gateway only sees the request in flight: it cannot verify an owner-signed delegation for that specific agent or emit a signed receipt another system can verify without trusting the gateway's database | Checks an owner-signed chain of permission (owner to agent identity to scoped permission with spend cap, expiry and instant revoke) before the tool executes, and emits a signed receipt after |
| **Multi-agent handoffs & state** | Unstructured RAG memory (Mem0, Zep, vector chunks) and raw JSON/markdown passed between agents (LangGraph, CrewAI) | Unstructured chunks carry no active/revoked status or signer authority, so agents read full historical documents to guess which rule is current. Forwarded text carries no proof of what the upstream agent actually read or produced | Stores typed, revocable, owner-signed state (`rules`, `instruction`, `receipts`) and passes a signed receipt between agents |
| **Portable verification** | Point-to-point identity, wallet or domain checks (Stripe Identity, Sumsub, OAuth) trapped inside one app's database | Every downstream app, partner or agent forces the user through the vendor check again and pays the vendor fee again | Wraps the verified result (ZKPassport, Webacy, DNS, OAuth) in a portable CAIP-380 proof so downstream apps and agents check eligibility without re-running the vendor flow |

When one agent hands a finished result to another in a multi-agent workflow (such as LangGraph, CrewAI or AutoGen), the receiving agent normally has two bad options: trust the forwarded markdown/JSON string blindly, or pay to re-run the upstream research from scratch. With Proofable, the producing agent emits a 66-byte signed receipt (`qHash`) binding the input, policy state and output, and the receiving agent verifies that receipt before acting.

Across three downstream tasks on the live service, checking the signed receipt cost **$0.024 per correct outcome** (33,240 total tokens across 2 model calls per task) against **$0.078 to redo the work** (124,715 total tokens across 3 to 5 model calls per task). Trusting the forwarded text costs the least of the three at **$0.009** per attempt on untouched input, and it is the only one that hands the downstream agent the wrong answer. When the forwarded text was modified in transit, agents that trusted the forwarded text used the tampered value **3 of 3 times**; agents that checked the signed receipt caught every change **3 of 3 times** and completed every task. Across a 10-hop agent chain over the 15 published records, passing the signed proof reference carried **9,900 bytes** per hop instead of **289,410 bytes** of full evidence (**29.2× smaller** handoff payload).

*Measured October 14, 2026 on the live service: three public downstream tasks, one run for each option, code-graded, with a separate producer and consumer agent on the same model. Dollar figures are the runtime token counts priced at the Claude Sonnet 5.5 list rate ($2 input / $10 output per million tokens).*

<img className="evid-dark evid-tall" src="/images/evidence/save-vault-stacked-dark.svg" alt="Reading typed Proofable state used 105,347 tokens in 56 seconds across 7 model calls, against 4,462,980 tokens in 493 seconds across 55 model calls for full-text keyword search over record bodies." />

Most agent memory layers (such as Mem0, Zep or vector file stores) return top-k text chunks with no active/revoked status and no signer, so the agent keeps reading full bodies to work out which rule is current. Proofable stores state as typed, revocable, owner-signed records (`rules`, `instruction`, `receipts`), so the agent queries active state by type and reads about 1 KB of verified metadata before opening a body.

On a live 1,721-record production vault, answering the same code-graded questions by typed lookup used **105,347 tokens in 56 seconds** (7 model calls) against **4,462,980 tokens in 493 seconds** (55 model calls) searching record bodies by keyword: **42.4× fewer tokens** and **8.8× faster**. At list prices that is $0.0628 vs $0.9161 on Claude Sonnet 5.5 (14.6×), and 18.4× to 18.9× lower on Gemini 3.1 Pro and GPT-6 Astra. On three direct probes, typed lookup ranked the target record first every time from about 1 KB of metadata; keyword search returned 61 KB to 63 KB of bodies, ranked the right plan fourth, and found nothing for the active model-provider rule.

*Method disclosure: Measured October 14, 2026 on the live service with the same agent and model on both options (one run each). This benchmark compares typed, active-state metadata filtering (querying by record scope and active status before fetching a body) against unstructured full-text keyword search over record bodies without type or status filters; it is not an embedding-similarity benchmark.*

Live web pages change between requests and cause unpredictable token spikes when agents re-scrape them. During our October benchmark runs, two fetches of the same URL 221 seconds apart returned 96,713 characters on the first request and 1,129 characters on the second, giving two agents different evidence with no way to prove what the page said when the decision was made. Across six code-graded public questions on standards, agent protocols and regulation, reading curated, signed Proofable records halved the cost per correct answer (**$0.020 vs $0.039** at Claude Sonnet 5.5 list price; 87,547 vs 136,088 total tokens) and capped worst-case token spend at **16,301 tokens** (40.7 s p95) where open-web search blew out to **50,554 tokens** and 104.3 s on a single regulatory question (**3.1× lower worst-case tail**, 1.3× spread vs 6.1× spread), while citing a checkable source on **6 of 6 answers** (vs 5 of 6 on the open web).

*Measured October 14, 2026 on the live service: six public questions, one run for each option, same agent and model. Both options answered 6 of 6 correctly, so this sample measures cost ceiling, tail variance and provenance rather than accuracy.*

## Run it yourself

Time a reuse on your own machine, with no account and no API key:

```sh
git clone --depth 1 https://github.com/proofable/docs
cd docs/public/evidence/checks
npm install
node reuse-check.mjs
```

It reads a finished job by its id and verifies the signed receipt on your machine:

```text
Record 0xcf67dcc3cc9c203136daf9905a422601652fd76cce437e2cbf56967e3a8117e6
Signature valid offline: yes
Read by id, no account: 197 ms median over 10
Verify offline: 4.2 ms median over 10
AI tokens used: 0
```

Pass any public record id to time that record instead.

Rerun the eight tests on any account you control with the kit in [Run the chain](/run-the-chain#run-it-end-to-end). To put receipts on your own agent's work, [add Proofable to your AI tool](/mcp/setup).

### Run it on every pull request

Add one workflow file and the same eight cases run in your CI, on your account, with every record verified offline and kept as a build artifact:

```yaml
- uses: proofable/docs/public/evidence/aaif/authority-at-dispatch/action@<commit-sha>
  with:
    access-key: ${{ secrets.PROOFABLE_ACCESS_KEY }}
    operator: ${{ github.repository_owner }}
    kit-ref: <commit-sha>
```

Pin both refs to the same commit so a rerun measures the same kit. The action writes a `trustharness.report/v1` report with each case's outcome, whether each record verified offline and the revision observed, and fails the job when the offline check fails. [Action and report schema](https://github.com/proofable/docs/tree/main/public/evidence/aaif/authority-at-dispatch/action).

## How the AgentGovBench run works

[AgentGovBench](https://github.com/agentic-control-plane/agentgovbench) is an open library of 48 agent-governance scenarios in eight areas: audit completeness, cross-tenant isolation, delegation provenance, fail-mode discipline, identity propagation, per-user policy, rate limits and scope inheritance. Each scenario is tagged with the NIST AI RMF controls it tests. Its maintainers revised the library in October 2026 so that nothing passes on a technicality.

We ran the current library (commit `479c5f0`) against the exact policy code the live service runs, matched to it by hash, next to a gate that allows everything and no governance at all. The run called that code directly, so it measures the decision logic rather than the hosted service end to end. Last run: October 20, 2026.

| Setup, current library | Scenarios handled |
|---|---|
| Proofable policy engine | 48 of 48 |
| ACP, the maintainers' gateway, live ([published run](https://github.com/agentic-control-plane/agentgovbench/actions/runs/37759892335)) | 46 of 48 |
| A gate that allows everything | 20 of 48 |
| No governance | 5 of 48 |

On the earlier library (commit `e0ce93a`) the same engine also handles 48 of 48, where the maintainers measured the agent tools teams already use:

| Setup, earlier library | Scenarios handled |
|---|---|
| Proofable policy engine | 48 of 48 |
| Anthropic Agent SDK with the ACP gateway | 46 of 48 |
| OpenAI Agents SDK with the ACP gateway | 45 of 48 |
| Claude Code or Codex CLI with ACP hooks | 43 of 48 |
| CrewAI or LangGraph with the ACP gateway | 40 of 48 |
| Cursor with ACP over MCP | 37 of 48 |
| Claude Code, Codex CLI, Cursor, the OpenAI or Anthropic agent SDK, CrewAI or LangGraph on its own | 13 of 48 |

The agent-tool rows are the maintainers' [published results](https://github.com/agentic-control-plane/agentgovbench/tree/main/results), run end to end against their gateway on the earlier library. Same scenarios and scorer, different setups: the tables compare what each approach covers.

**Why standalone agents handle 13, the reference gateway handles 46, and Proofable handles 48:**

- **Standalone coding agents (13 of 48):** Claude Code, Codex CLI and Cursor only have local tool-permission prompts (`allow/deny` bash or file access). They have no owner-bound agent identity, no cross-agent delegation, no spend caps, no external policy engine, and no signed audit trail.
- **Stateless API/MCP gateway (46 of 48):** A proxy gateway in front of tool calls enforces rate limits, role-based access, tool allowlists, and server logs, which covers 46 of the 48 checks.
- **The final 2 checks a stateless gateway cannot do (48 of 48):** A proxy gateway only sees the HTTP or MCP request in flight. It cannot verify (1) an **owner-signed, revocable delegation** binding the human principal to that specific agent identity, task scope, spend cap and expiry (such as holding a sub-agent to a narrower scope than its parent), or (2) a **signed execution receipt** (`qHash`) binding the input, policy state and output so a downstream agent or external reviewer can verify what ran offline without trusting the gateway's database.

**See what your agent does with and without Proofable.** Paste your agent's repository and one run reports your score on the same 48 scenarios beside Proofable's, a scan of the repository and its MCP surface, and a probe of your MCP endpoint when the repository names one: [run the audit on your own agent](https://proofable.me/verify?gateId=gate_25cfeb508d484170a2ce). Every script behind the run is public in [`public/evidence/benchmarks`](https://github.com/proofable/docs/tree/main/public/evidence/benchmarks), pinned by commit and checksum.

## Unit economics of portable verification reuse

Unlike the live LLM and governance runs above, portable identity reuse is a **pricing model** calculated from published vendor list prices (`stripe.com/pricing`, `sumsub.com/pricing`, `veriff.com/pricing`, `onefootprint.com/pricing`) and Proofable's $0.0025 per-check list rate. When a person or organization completes an interactive check once and wraps the result in a portable proof, downstream apps and agents verify the existing proof instead of paying the vendor to re-run the flow:

| Vendor check | 100 relying parties, re-verified each time | 100 relying parties, verify once + reuse | Published source |
|---|---|---|---|
| Stripe Identity ($1.50 pay-as-you-go) | **$150.00** (100 flows) | **$1.75** (1 flow + 100 checks, 85× lower) | stripe.com/pricing |
| Sumsub Basic ($1.35 per check) | **$135.00** (100 flows) | **$1.60** (1 flow + 100 checks, 84× lower) | sumsub.com/pricing |

| Footprint KYC ($0.50 per check) | **$50.00** (100 flows) | **$0.75** (1 flow + 100 checks, 67× lower) | onefootprint.com/pricing |
