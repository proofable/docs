With Proofable, every finished agent job carries a signed receipt. The next agent checks the receipt instead of paying to redo the job.

AgentGovBench is the open benchmark for agent governance: 48 scenarios such as a sub-agent reaching past its parent's limits or one customer's data reaching another. The agent-tool rows are the maintainers' published results on the earlier version of the library, where Claude Code, Codex CLI and Cursor each handle 13 on their own. On the current version, run October 20, 2026 against the policy code the live service runs, Proofable handles all 48 and ACP, the maintainers' own gateway, handles 46.

**8 of 8 permission tests passed on the live service.** Every action outside the agent's permission was stopped before it ran, and the actions it was allowed to take ran.

**150 of 150 forged records caught.** We changed each of our 15 real records ten ways. Every changed copy failed verification and every real record passed.

## Test it in a minute

Time a reuse on your own machine, with no account and no API key:

```sh
git clone --depth 1 https://github.com/proofable/docs
cd docs/public/evidence/checks
npm install
node reuse-check.mjs
```

It reads a finished agent job by its id, verifies the signed receipt locally, and prints the time and the AI tokens used. Expect a few milliseconds and zero tokens. Pass any public record id to time that record instead.

To put receipts on your own agent's work, [add Proofable to your AI tool](/mcp/setup).

  <Accordion title="Try to fake a record">
    This check takes the 15 real records and changes each one ten ways, such as editing the content, swapping the owner or flipping one bit of the signature. Then it verifies every copy. All 150 changed copies fail and all 15 real records pass. A check that only looks at the format would accept every changed copy.

    ```sh
    git clone --depth 1 https://github.com/proofable/docs
    cd docs/public/evidence/checks
    npm install
    node tamper-check.mjs
    ```

  <Accordion title="How the AgentGovBench run works">
    [AgentGovBench](https://github.com/agentic-control-plane/agentgovbench) is an open library of 48 agent-governance scenarios in eight areas: audit completeness, cross-tenant isolation, delegation provenance, fail-mode discipline, identity propagation, per-user policy, rate limits and scope inheritance. Each scenario is tagged with the NIST AI RMF controls it tests. Its maintainers revised the library in October 2026 so that nothing passes on a technicality.

    We ran the current library (commit `479c5f0`) against the exact policy code the live service runs, matched to it by hash, next to a gate that allows everything and no governance at all. The run called that code directly, so it measures the decision logic rather than the hosted service end to end. Last run: October 20, 2026.

    | Setup, current library | Scenarios handled |
    |---|---|
    | Proofable policy engine | 48 of 48 |
    | ACP, the maintainers' gateway, live ([published run](https://github.com/agentic-control-plane/agentgovbench/actions/runs/37759892335)) | 46 of 48 |
    | A gate that allows everything | 20 of 48 |
    | No governance | 5 of 48 |

    On the earlier library (commit `e0ce93a`) the same engine also handles 48 of 48, where the maintainers measured the agent tools teams already use:

    | Setup, earlier library | Scenarios handled |
    |---|---|
    | Proofable policy engine | 48 of 48 |
    | Anthropic Agent SDK with the ACP gateway | 46 of 48 |
    | OpenAI Agents SDK with the ACP gateway | 45 of 48 |
    | Claude Code or Codex CLI with ACP hooks | 43 of 48 |
    | CrewAI or LangGraph with the ACP gateway | 40 of 48 |
    | Cursor with ACP over MCP | 37 of 48 |
    | Claude Code, Codex CLI, Cursor, the OpenAI or Anthropic agent SDK, CrewAI or LangGraph on its own | 13 of 48 |

    The agent-tool rows are the maintainers' [published results](https://github.com/agentic-control-plane/agentgovbench/tree/main/results), run end to end against their gateway and not re-measured on the current library. The Proofable rows call the policy code directly. The scenarios and scorer are the same and the setups are not, so read the tables as a comparison of what each approach covers, not as a ranking. Proofable also handles the one scenario ACP declines: holding a sub-agent to a narrower task than its parent.
  </Accordion>
