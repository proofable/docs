Every registered Proofable agent has a **public card**: owner, identity, capabilities, and current status other apps can check.

That card is the portable record. Other marketplaces can list the same agent. Proofable keeps identity, control, and proof state in one place.

## Discovery paths

| Path | URL | Returns |
|------|-----|---------|
| Agent page | `https://proofable.me/agent/{agentId}` | Human-readable profile |
| Universal JSON | `https://proofable.me/api/agent/{agentId}?format=json` | Identity + permissions + proofs |
| A2A (per agent) | `https://proofable.me/api/agent/{agentId}?format=a2a` | Agent-to-Agent card |
| A2A (platform) | `https://proofable.me/.well-known/a2a/agent-card.json` | Platform-wide A2A card |
| Platform metadata | `https://proofable.me/.well-known/agent-card.json` | Service discovery and registration status |
| Per-agent metadata | `https://api.proofable.me/.well-known/agent-card.json?agentId={agentId}` | Per-agent discovery metadata |

Per-agent cards resolve to `GET https://api.proofable.me/api/v1/agents/card/{agentId}`. The platform A2A card is also available at `/api/agent/config?format=a2a`. Proofable is not currently registered on ERC-8004; the platform metadata reports that status explicitly.

## Examples

```bash
# Human profile
# https://proofable.me/agent/my-support-agent

# Full Proofable JSON
curl https://proofable.me/api/agent/my-support-agent?format=json

# A2A card for this agent
curl https://proofable.me/api/agent/my-support-agent?format=a2a

# Platform A2A card
curl https://proofable.me/.well-known/a2a/agent-card.json
```

## What a card shows

| Field | Source | Visible |
|-------|--------|---------|
| `agentId` | Identity proof | Public |
| `agentWallet` | Identity proof | Public |
| `agentLabel` | Identity proof | Public |
| `description` | Identity proof | Public |
| `capabilities` | Identity proof | Public |
| `skills` | Identity proof | Public |
| `controllerWallet` | Permission proof | Public |
| `scope` | Permission proof | Public |
| `allowedActions` | Permission proof | Owner-view only |
| `deniedActions` | Permission proof | Owner-view only |

Public cards do not expose full allow/deny lists. External callers see who the agent is and who approved it, not the full permission matrix.

## Visibility

An agent **is** its identity proof, so it has exactly one visibility setting, the same
three values every Proofable proof has. The setting covers the whole agent, including
its instructions.

| Setting | Who can open the card | Listed in search and feeds |
|---------|----------------------|----------------------------|
| **Public** | Anyone | Yes |
| **Unlisted** | Anyone with the link | No |
| **Private** | The owner, plus people the owner grants access to | No |

**Unlisted is link-addressed**, exactly like a proof: `GET` on the card by its own URL
returns it to any caller, and it simply never appears in a listing. Do not treat
"not discoverable" as "not fetchable". An unlisted agent is meant to be handed to
someone directly.

A **Private** agent:

- answers `403` with `error.code = "AGENT_NOT_PUBLIC"` to a caller with no access,
  so you can distinguish "exists but not shared with you" from `404 AGENT_NOT_FOUND`;
- opens fully for the owner and for anyone holding a live **access grant** on that
  agent's identity proof.

Grants are per-record and per-viewer, created by the owner
(`POST /api/v1/verification/access/grant`) and stored against the identity proof's
`qHash`. Fetching a private agent as a granted viewer behaves identically to
fetching it as the owner. An expired or revoked grant falls back to `403`.

The owner changes visibility from the agent's own Share sheet, which edits the
identity proof in place; the change takes effect on the same link immediately.

## CORS and caching

Discovery endpoints return `Access-Control-Allow-Origin: *`. Platform cards cache for about an hour; per-agent cards cache for about five minutes.

A card served to its **owner** is never cached publicly: the response carries the
viewer marker and must not be replayed to a later visitor.

## Platform A2A card

The platform card includes registered skills, MCP / REST / payment interfaces, auth options (OAuth and server keys), and networks listed by CAIP-2 id.

## How to use it

1. **Discover**: fetch the card for the agent you need.
2. **Confirm**: check the permission proof before a sensitive action.
3. **Connect**: call the agent through MCP, A2A, or your own runtime.
