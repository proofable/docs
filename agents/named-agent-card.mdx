Every registered Proofable agent has a **public card** with its owner, identity, capabilities, and current status. Other marketplaces can list the same agent while Proofable keeps its identity, control, and proof state in one place.

## Discovery paths

| Path | URL | Returns |
|------|-----|---------|
| Agent page | `https://proofable.me/agent/{agentId}` | Human-readable profile |
| Universal JSON | `https://proofable.me/api/agent/{agentId}?format=json` | Identity + permissions + proofs |
| A2A (per agent) | `https://proofable.me/api/agent/{agentId}?format=a2a` | Agent-to-Agent card |
| A2A (platform) | `https://proofable.me/.well-known/a2a/agent-card.json` | Platform-wide A2A card |
| Platform metadata | `https://proofable.me/.well-known/agent-card.json` | Service discovery and registration status |
| Per-agent metadata | `https://api.proofable.me/.well-known/agent-card.json?agentId={agentId}` | Per-agent discovery metadata |

Per-agent cards resolve to `GET https://api.proofable.me/api/v1/agents/card/{agentId}`. The platform A2A card is also available at `/api/agent/config?format=a2a`. ERC-8004 registration metadata is published at `https://proofable.me/.well-known/agent-registration.json` for 8004 indexers. On-chain registry status appears in the platform metadata as `erc8004.registered`, which is currently `false`.

## Examples

```bash
# Human profile
# https://proofable.me/agent/my-support-agent

# Full Proofable JSON
curl https://proofable.me/api/agent/my-support-agent?format=json

# A2A card for this agent
curl https://proofable.me/api/agent/my-support-agent?format=a2a

# Platform A2A card
curl https://proofable.me/.well-known/a2a/agent-card.json
```

## What a card shows

| Field | Source | Visible |
|-------|--------|---------|
| `agentId` | Identity proof | Public |
| `agentWallet` | Identity proof | Public |
| `agentLabel` | Identity proof | Public |
| `description` | Identity proof | Public |
| `capabilities` | Identity proof | Public |
| `skills` | Identity proof | Public |
| `controllerWallet` | Permission proof | Public |
| `scope` | Permission proof | Public |
| `allowedActions` | Permission proof | Owner-view only |
| `deniedActions` | Permission proof | Owner-view only |

Public callers see who the agent is and who approved it. The full allow and deny lists are visible to the owner only.

## Visibility

An agent is its identity proof, so it has one visibility setting with the same three values every Proofable proof has. The setting covers the whole agent, including its instructions.

| Setting | Who can open the card | Listed in search and feeds |
|---------|----------------------|----------------------------|
| **Public** | Anyone | Yes |
| **Unlisted** | Anyone with the link | No |
| **Private** | The owner, plus people the owner grants access to | No |

An **Unlisted** card is link-addressed, like a proof: a `GET` on its URL returns it to any caller, and it never appears in a listing. Hand it to someone directly.

A **Private** agent:

- answers `403` with `error.code = "AGENT_NOT_PUBLIC"` to a caller with no access, so you can tell "exists but not shared with you" apart from `404 AGENT_NOT_FOUND`;
- opens fully for the owner and for anyone holding a live **access grant** on that agent's identity proof.

The owner creates grants per record and per viewer (`POST /api/v1/verification/access/grant`), stored against the identity proof's `qHash`. A granted viewer sees the agent exactly as the owner does. An expired or revoked grant falls back to `403`.

The owner changes visibility from the agent's Share sheet, which edits the identity proof in place. The change takes effect on the same link immediately.

## CORS and caching

Discovery endpoints return `Access-Control-Allow-Origin: *`. Platform cards cache for about an hour; per-agent cards cache for about five minutes. A card served to its **owner** is never cached publicly.

## Platform A2A card
