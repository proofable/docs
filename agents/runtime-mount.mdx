To load the same agent into an editor project:

```bash
npx -y @proofable/sdk setup
npx -y @proofable/sdk mount my-agent --apply cursor
```

Valid `--apply` values are `cursor`, `claude`, `codex`, `hermes`, `openclaw`, and `opencode`. VS Code uses `--apply cursor`. The command writes `.proofable/mount.json` and the host adapter. Hermes, OpenClaw, and OpenCode also get a pointer to that file at `.hermes/proofable.json`, `.openclaw/proofable.json`, or `.opencode/proofable.json`. Start a new session so the project picks it up.

The editor runs the tools. Proofable supplies identity, limits, and proofs. Cursor Cloud Agents connect to the same hosted MCP endpoint from the VMs Cursor runs.

## From the agent card

**Connect in** copies the same command for the agent:

```bash
npx -y @proofable/sdk mount <agentId> --apply <host>
```

Run it in the project. If the host is not connected yet, run `proofable setup` first. Host files are written by this command, never by the browser.

## Assistant tool

When signed in, call **`proofable_agent_mount`** with `agentId`, `agentWallet`, or the identity proof ID in `identityQHash`.

Suggested order:

1. `proofable_context`
2. `proofable_agent_mount` when acting as a specific agent
3. `proofable_verify_or_guide` before sensitive actions; use `proofable_proofs_check` only for an explicit yes/no eligibility, gate, or access question

## SDK

```javascript
import { resolveRuntimeBundleFromMcp } from '@proofable/sdk/runtime-mount';
import { applyRuntimeBundle } from '@proofable/sdk/runtime-adapters';
```

Use `resolveRuntimeBundleFromMcp` with your MCP transport, then `applyRuntimeBundle(host, bundle, cwd)` for project files. The `proofable_agent_mount` MCP tool and the `proofable mount` CLI return the same bundle shape.

## Enforcement

Your client runs its own tools and enforces the mounted permissions in its own tool loop. Proofable enforces them directly for chat and jobs on Proofable. [Agents](/agents#where-permissions-are-enforced) compares each surface, and [your first guarded action](../mcp/guarded-action) shows the check in code.
