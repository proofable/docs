## Rate limits now scale with your plan

- **New proofs scale with the plan.** Creating proofs was capped at 50 per 15 minutes on every plan. It is now a per-minute budget: 30 a minute on Free, 120 on Pro, 300 on Enterprise. API calls stay at 60, 240 and 600 a minute.
- **The budget follows the account that pays.** A signed-in account or access key is counted on its own wallet, including when it writes into one of its agents' vaults. A wallet-signed request with no session is counted on the wallet that signed it.
- **One count across the service.** Limits are counted once for the whole service rather than per server, so the number in `RateLimit-Policy` is the number you get.

Read the headers and the retry pattern in [Rate limits](/api/rate-limits).

</Update>

## Talk to a hosted agent from any app, and read your spend

`@proofable/sdk@0.1.11` adds two client calls.

- **`client.agentChat()` talks to a hosted agent.** Name the agent and send the conversation. The turn runs on Proofable as that agent, under the delegation you signed for it, and every tool call is checked before it runs. Events stream to `onEvent`, and the call resolves with the answer, the records the agent read as `citations`, and the credits it spent. See [Talk to your agent from any app](/agents/talk-to-an-agent).
- **`client.getUsage()` reads your credits and spend:** the balance, recent spend events, and spend by line and by UTC day, for any period with `from` and `to`.

```bash
npm install @proofable/sdk@0.1.11
```

</Update>

## Verify any CAIP-380 envelope, import an agent in one step

`@proofable/sdk@0.1.10` covers 0.1.7 through 0.1.10.

- **Any CAIP-380 envelope verifies (0.1.9).** `verifyPortableProofEnvelope` takes the signer from the envelope's `did:pkh` identifier, so an envelope without `walletAddress`, including the specification's test vectors, verifies instead of throwing. Use 0.1.9 or later to verify envelopes from other implementations.
- **`proofable import` creates the agent (0.1.10).** A signed-in terminal creates the agent on your profile with its full instructions and mounts it into the current project. `--expires-at` sets an end to its permissions, `--no-mount` skips the mount, and `--dry-run` shows what would happen.
- **`proofable auth --oauth` signs in the CLI only (0.1.10).** It no longer writes its short-lived token into your editors; pass `--client` to write it to one.
- **`fulfillGate()` completes AI service orders (0.1.7).** It sends `serviceParameters` for the listing's `serviceInputs`, and the run's answer appears on the buyer's receipt at `meta.marketplace.serviceJob.result`.
- **The CLI exits with code 1 after an error on Windows (0.1.8),** and a dry-run mount lists files as "would write".

```bash
npm install @proofable/sdk@0.1.10
```

</Update>

<Update
  label="September 25, 2026"
  description="Checking a proof is free"
  tags={["API", "Docs", "Pricing"]}

    description: "Checks against an existing proof no longer cost credits. You pay only to create a proof."

## Checks are free

Checking an existing proof now costs **0 credits**. You pay only when you create a new proof.

- `GET` and `POST /api/v1/proofs/check` are free. Rate limits per plan are the only control.
- Per-request surcharges for verifier count, query complexity, time window, and result limit are removed.
- `/api/v1/proofs/check` is no longer an x402 pay-per-call resource. Proof creation and share grants still are.
- Access grants are a flat 2 credits. Duration tiers (`perHour`, `maxDurationBonus`) were removed; the grant's own duration limit is enforced where the grant is created.

Reuse is the point of a portable proof, so checking one is free and rate-limited rather than metered. See [Pricing](/pricing) and [Reuse verification](/use-cases/reuse-verification).

</Update>

## Agent authority, listed explicitly

An agent's authority is what its delegation lists, not a scope string. `allowedActions` minus `deniedActions` is the grant, and a delegation with no listed actions grants nothing.

- Delegations require `allowedActions` and only accept canonical action names.
- Spend authority is bounded: `make_payment` needs `allowedPaymentTypes` and `maxSpend` together.
- App agents list the web origins they may act from in `allowedOrigins`, or `"*"` for servers.
- Revoked, superseded, and expired delegations grant nothing.

```bash
npm install @proofable/sdk@0.1.2
```

</Update>

## Builder path without a listing

Define the checks in your app. Check the visitor by account. Reuse a current proof. Verify only what is missing.

- `defineGate` + `gateCheck({ gate, subject })` does not create a Proofable profile.
- `POST /api/v1/proofs/check` takes the same x402 pay-per-call rail as `GET`.
- MCP sign-in stays OAuth. Machine API calls stay x402, sponsor, or credits.
- `gateCheck({ gateId })` still works for published listings.

## One description per public surface

GitHub, npm, the MCP Registry, and product pages no longer repeat the product line. Each surface now carries its own description, so search and directories show what that surface is instead of one slogan everywhere.

- MCP package and registry: Give AI agents identity, scoped access, trusted context, and verifiable actions through MCP.
- SDK package: SDK and CLI for verification gates, reusable proof, and agent permissions.
- Docs: Docs for verification, gates, proofs, agents, and MCP.
- The category line stays the remembered brand: The trust harness for AI.
- Release notes now summarize the predecessor `@neus` releases in one readable [history section](#history).

```bash
npm install @proofable/sdk@0.1.1
```

</Update>
