Use when you need a proof by ID or need to find proof records, tags, or content. Omit **`identifier`** when signed in to search the current account. For a yes/no eligibility answer, use **`proofable_proofs_check`**. Profile totals come from **`proofable_context`**.

| Auth | Visibility |
|------|------------|
| None | Public-scope view |
| Bearer | Can include **private** proofs for that account ([Auth](./auth)) |

## Common reads

| Need | Use |
|------|-----|
| Find one known proof | Pass `qHash` |
| Browse all proofs | Pass `scope: "all"` for paginated metadata |
| Reuse assistant context | Use a narrow `scope` such as `memory` or an exact `tags` value |
| Confirm an agent handoff | Include `agentWallet` for delegated reads |
| Find related records | Use `tagPrefix`, `tagContains`, `tagPrefixesAll`, `verifierId`, or `q` |

## Input

```json
{
  "scope": "memory",
  "limit": 5,
  "offset": 0,
  "include": "content"
}
```

| Field | Notes |
|-------|-------|
| `identifier` | Wallet address or **`did:pkh:...`**; optional when signed in |
| `scope` | Category preset (`memory`, `research`, `rules`, `instruction`, `tools`, `jobs`, `receipts`) or `all` for a whole-account metadata list |
| `tags` | Exact tags, as an array or one comma-separated string. A proof matches any one. Takes precedence over `scope` |
| `tagPrefix`, `tagContains` | Match the beginning of a tag or text within a tag |
| `tagPrefixesAll` | Prefixes that must each match a tag, as an array or one comma-separated string |
| `verifierId`, `q` | Filter by check ID or search text |
| `agentWallet` | Delegation (**`x-agent-wallet`**) |
| `limit`, `offset` | Page size (default 15, max 25) and offset |
| `include` | Defaults to `metadata`; `content` requires a known proof ID or narrowing filter and is capped for list reads |
| `qHash` | When set, returns that one record instead of a vault page |
| `includeComments` | Set `true` with `qHash` to include comments visible to the signed-in account. Private proof comments are available to the owner |

When `identifier` is a DID, Proofable resolves the DID to its native account. Non-EVM signing and account context still use CAIP-2 `chain`; see [CAIP-380 Portable Proof](../learn/standards/caip-380).

## Response

With no ID or filter, the tool returns an index hint instead of a vault page. `scope: "all"` returns paginated metadata. `include: "metadata"` returns proof ID, status, check IDs and outcomes, title, tags, timestamps, and content length when known; bodies and the profile summary are left out. With `includeComments: true`, comments appear under `data.feedback.comments`.

Use `include: "content"` for a specific proof or tightly filtered page when the body is required. A whole-vault read does not unlock bodies. Filtered content lists are capped at five records by default, so inspect pagination before inferring absence. A failed upstream read returns an error. A known `qHash` read returns its stored `portableProof` envelope to the owner, and to anyone for a public proof whose owner enables disclosure.

## Assistant output

Summarize the result in plain language and link only real proof URLs returned by Proofable:

```txt
Proofable: Passed. Requirement satisfied. Result on file. Next: Continue.
```

Avoid raw JSON, private implementation tags, or guessed proof URLs.
