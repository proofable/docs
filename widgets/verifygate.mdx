`VerifyGate` checks eligibility, opens Hosted Verify when a new check is needed, then renders your protected content. Point it at a published gate, which owns verifier inputs, pricing, and checkout policy.

## Quickstart

1. [Create a listing](https://proofable.me/profile/portals/new) and choose the checks visitors must pass. Manage published listings from [Listings in your profile](https://proofable.me/profile?tab=portals).
2. Publish the gate and copy your checkout link or embed snippet.
3. Paste the embed in your app, or send users to the hosted link.
4. Optionally run `gateCheck` on your server before granting access.

```jsx
import { VerifyGate } from '@proofable/sdk/widgets';

export function Page() {
  return (
    <VerifyGate gateId="gate_your-app-name">
      <div>Unlocked</div>
    </VerifyGate>
  );
}
```

```js
import { getHostedCheckoutUrl } from '@proofable/sdk';

const url = getHostedCheckoutUrl({
  gateId: 'gate_your-app-name',
  returnUrl: 'https://app.example.com/continue',
});
```

```js
import { ProofableClient } from '@proofable/sdk';

const client = new ProofableClient();
const result = await client.gateCheck({
  gateId: 'gate_your-app-name',
  address: user.walletAddress,
});
```

With a `gateId`, billing and check policy come from the gate, so there is no app registration or `billingWallet` to pass.

## Key props

| Prop | What it does |
|------|--------------|
| `gateId` | Published gate handle |
| `strategy` | `reuse-or-create` (default), `reuse`, or `fresh` |
| `mode` | `create` (default) opens Hosted Verify; `access` has the wallet sign to read the private proof in `qHash` |
| `qHash` | Proof to read in access mode |
| `hostedCheckoutUrl` | Override the Hosted Verify base URL |
| `oauthProvider` | Pre-select a social or org sign-in on Hosted Verify |
| `wallet` | Optional signer for private proof reuse or access mode |

## Hosted OAuth

Social, organization, and human checks run on [Hosted Verify](../verification/hosted). Set `oauthProvider` when the user already picked a provider in your app:

- **Social:** `x` (or `twitter`), `github`, `discord`, `linkedin`
- **Org:** `google`, `microsoft`, `email`

## Server-created proofs

For backend-created proofs after a one-time user approval, use the `verifyFromApp` flow in [Server integrations](../integrations/server). Keep browser checkout on `gateId`.
