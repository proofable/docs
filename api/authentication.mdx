Most products use Hosted Verify for people and a server key for backend calls. Creating a proof uses credits; sign-in and checks against existing proofs are free. [Pricing](../pricing)

| Need | Mechanism | Wallet code in your app |
|------|-----------|---------------------------|
| Sign-in for your app | Hosted Verify + `intent=login` + `returnUrl` | No |
| Access or checkout (default) | `VerifyGate` / Hosted Verify + `gateId` | No |
| MCP client sign-in | OAuth 2.0 + PKCE | No |
| Server automation as your profile | Bearer `npk_*` access key | No |
| Server creates proofs for an approved user | App link + `verifyFromApp` | No |
| Sign inside your page | SDK `verify` + `wallet` | Yes. Rare |

## Hosted Verify (default)

Send people to `https://proofable.me/verify` ([Hosted Verify](../verification/hosted)). With a `gateId`, your credits cover the checks unless the listing charges visitors a price.

## MCP OAuth

MCP clients authenticate via **OAuth 2.0 Authorization Code with PKCE**. Register `https://mcp.proofable.me/mcp` and finish the sign-in your client opens. Official CLI: `npx -y @proofable/sdk`.

Request only the scopes you need:

| Scope | What it allows |
|-------|-----------------|
| `proofable:core` | Public protocol tools |
| `proofable:profile` | Signed-in profile context |
| `proofable:secrets` | Portable encrypted secrets |
| `offline_access` | Refresh token |

See [Add Proofable to any MCP client](../mcp/setup) and [MCP OAuth](../mcp/oauth).

## Server keys

[Access keys](https://proofable.me/profile?tab=account) (`npk_*`) carry full profile access. Use them for servers, CI, and MCP automation, and keep them out of browser bundles.

## Backend proofs

For backend-created proofs after a user approves your product once, see [Server integrations](../integrations/server). Separate from [creating a listing](https://proofable.me/profile/portals/new), which bills hosted verification to your account.
