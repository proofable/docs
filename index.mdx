## Build with Proofable

Define requirements in your code, check existing proof on your server, verify only what is missing, then make the final decision in your product.

- You do not need to publish a Gate.
- You do not need the Proofable dashboard.
- Proofable checks existing proof before asking the user to verify again.
- Your application owns the final allow or deny decision.

```ts
import { ProofableClient, defineGate } from '@proofable/sdk';

const proofable = new ProofableClient();
const gate = defineGate([{ verifierId: 'proof-of-human' }]);

// Run this on your server before accepting the protected action.
const result = await proofable.gateCheck({
  gate,
  subject: { accountId: user.accountAddress },
});

if (!result.satisfied) {
  // Show VerifyGate or Hosted Verify for result.missing, then check again.
  throw new Error('Verification required');
}

await submitReview();
```

`defineGate()` is local and does not publish or persist anything. The check returns a decision, zero or more proof references in `result.proofs`, and the resolved subject identifier. [JavaScript SDK reference](/sdks/javascript)
